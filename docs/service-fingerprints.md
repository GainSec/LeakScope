# Provider query candidates — generated from executable profiles

Read `leakscope/phase3/catalog.py`, `fingerprints.py` and the five `profiles_*.py` data modules before changing behavior. This file is navigation data generated from those definitions; it does not prove provider acceptance, indexed recall or live target identity.

The catalog has 127 profiles: 41 database, 23 storage, 23 ot, 12 messaging, 14 web, 14 iot. Candidate definitions: shodan 126, zoomeye 127, netlas 126.

Default fingerprint candidates contain no port predicates. PLC explicitly uses a device taxonomy; other profiles may use response text, protocol classifiers, compatible protocol families or HTTP companions. gRPC and PLC have no universal reference port; their optional port modes are unavailable. Unsupported predicates are never dropped or replaced by port searches.

Shodan unqualified quoted text searches indexed response data; `shodan.module` values use the checked scanner snapshot. ZoomEye `service=` is application protocol; `protocol=` is transport. Netlas uses decoded fields, `prot7` or response text. Classifier aliases remain unvalidated against current live results.
